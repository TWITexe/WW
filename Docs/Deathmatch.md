# Комнаты и «Схватка»

В меню создания комнаты доступны название, флажок «Закрытая комната», пароль, режим «Схватка — каждый сам за себя» и два целочисленных слайдера: 1–30 минут и 1–33 убийства. Последние время и цель запоминаются; пароль на диск не сохраняется. Создать закрытую комнату с пустым паролем нельзя.

В списке LAN-комнат закрытые комнаты отмечены подписью. При входе открывается диалог пароля. Сервер Mirror проверяет HMAC-ответ на одноразовый запрос до создания игрока. В ответах discovery находятся только название, количество игроков, признак закрытой комнаты и настройки. Пароль в discovery не передаётся. При отказе показывается ошибка и разрешается повторный ввод.

Сервер завершает матч при первом выполненном условии: истечение времени или достижение цели убийств. После этого урон, движение и команды применения заклинаний блокируются, итоговая таблица фиксируется. Tab сортирует игроков по убийствам по убыванию, затем по смертям и сетевому ID. Таймер сверху по центру использует MM:SS; в последние 30% длительности цвет линейно переходит из белого в красный.

## Реванш

На экране «Итог схватки» есть «В меню», «Реванш», число готовых игроков и обратный отсчёт 01:00. После голосования отображается «Ожидание других игроков». Повторное голосование не учитывается. Если согласны все подключённые участники, новый раунд начинается сразу. По окончании минуты остаются только проголосовавшие; остальные возвращаются в меню. Если не согласился никто, комната закрывается.

Реванш перезагружает арену через Mirror ServerChangeScene, сохраняя соединения, название, пароль и правила комнаты. Это сбрасывает счёт, здоровье, перезарядки, эффекты и разрушения окружения. При выходе отказавшегося хоста комната передаётся согласившемуся участнику.

## Передача хоста

Для существующей LAN-сети участникам каждые 0,5 с отправляется снимок комнаты. При обычном выходе хост отправляет финальный снимок; при закрытии приложения используется последний полученный. Новым хостом становится первый оставшийся клиент из согласованного списка. Остальные автоматически подключаются к нему. Сохраняются настройки, пароль, счёт, оставшееся время, итоги и голоса реванша. Во время подключения отображается статус передачи комнаты.

Миграция выполняется с повторной загрузкой арены и новым появлением персонажей: текущие снаряды, позиции, здоровье и разрушения окружения не переносятся. Таймер на время переподключения приостанавливается. Новый хост должен быть доступен остальным в локальной сети по используемому UDP-порту; NAT relay и перенос на произвольную интернет-сеть не добавлялись. На ожидание переподключения участников перед ранним реваншем выделяется до 10 секунд; после возвращения всех ожидаемых участников ожидание снимается сразу. При невозможности подключения показывается ошибка.

## Интерфейс и проверка

Настройки комнаты — коричневые, с золотистыми слайдерами. Итоги и фоны всех карточек заклинаний — полупрозрачные чёрные и тёмно-серые. Иконки стихий сохраняют свои цвета.

UI сохранён в Menu.unity и MatchUI.prefab, доступен для ручного редактирования. DeathmatchUIBuilder.Apply обновляет только связанные элементы. Исходное несохранённое состояние меню перед первой установкой сохранено в Logs/DeathmatchBefore/Menu.unsaved.unity.

DeathmatchRegression.RulesAndAssets проверяет ограничения, формат и цвет таймера, защиту от неверного пароля/повтора запроса и ссылки HUD. RoomNetworkSmoke — явный opt-in драйвер многопроцессных проверок, включён только в Editor/Development Build, отсутствует в обычной сборке.

Проверено 23.09.2026:

- Unity Editor: компиляция без ошибок; Development Build Windows: Succeeded, 0 ошибок.
- Реальный Play Mode: слайдеры и их числовые значения, сохранённые ссылки, таймер, итоговый экран и фактические цвета всех карточек заклинаний.
- Многопроцессный тест с тремя одновременными участниками: неверный пароль, результаты по цели убийств и времени, блокировка урона после окончания, ранний реванш по общему согласию, обнуление счёта и сохранение правил.
- Миграция: добровольный выход хоста, закрытие его приложения, повторная передача хоста, сохранение ненулевого счёта, подключение нового участника к перенесённой закрытой комнате, освобождение состояния ожидания миграции.
- Реванш по дедлайну: возврат несогласившегося игрока в меню, передача комнаты при отказе хоста, закрытие комнаты без голосов.
